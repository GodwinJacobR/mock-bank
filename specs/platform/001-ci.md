# CI

Status: draft

## Goal
Every PR is checked for formatting, lints and tests.

## Scope (in)
- GitHub Actions workflow `.github/workflows/ci.yml`, triggered on `pull_request` and push to `main`.
- Steps: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`.
- Data-generation guard: fail if seed/mock data generation (crates `fake`/`faker`/`rand`, seed scripts or fixtures, bulk `INSERT` of sample rows) appears under `services/*`, `common/*` or `migrations/*`. Allowed via explicit allowlist in the script: the `bank:treasury` system-account rows in `migrations/ledger/0003_system_accounts.sql`, `rand` for account numbers in `services/accounts`, and `rand` in `services/web/src/admin/` for the random transfer generator. `fake`/`faker` are never allowed.
- Cargo caching (`Swatinem/rust-cache`).
- Docker available on the runner (ubuntu-latest) for testcontainers (Postgres, Kafka).

## Out of scope
- Image builds/publishing, deploys, coverage, release workflows.
- Branch protection settings (manual in GitHub).

## Design
- One job `check` on `ubuntu-latest`, stable Rust toolchain with `rustfmt` and `clippy`.
- Env `RUSTFLAGS=-D warnings` is not used; clippy handles it.
- Concurrency group per ref, cancel in-progress runs.
- Until the workspace exists (`platform/002-workspace-and-compose`), the workflow skips cleanly if no `Cargo.toml` is present.

## Dependencies
- None to start. Becomes meaningful after `platform/002-workspace-and-compose`.

## Acceptance criteria
- [ ] Workflow runs on every PR.
- [ ] Unformatted code fails the job.
- [ ] A clippy warning fails the job.
- [ ] A failing test fails the job.
- [ ] Adding faker/seed data generation under `services/*`, `common/*` or `migrations/*` fails the job.
- [ ] Tests using testcontainers run in CI.
- [ ] Second run on unchanged deps restores the cargo cache.

## Test plan
- Open throwaway PRs with a fmt error, a clippy warning, and a failing test; each must fail.
- Open a clean PR; it must pass, and the cache hit appears in the log on re-run.
